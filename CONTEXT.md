# CONTEXT — ai_system vocabulary

- **tdd-rules fragment** — `docs/tdd-rules.d/<R-NNN>.md`, one ship's learned TDD rules. Readers see the legacy `docs/tdd-rules.md` first, then every fragment by name.
- **security pass** — ship-next Phase 6 steps 1.5–1.6 (R-003): a vendored copy of Anthropic's `/security-review` prompt, run every review attempt next to code-review-skill. Its HIGH findings block like code-review blockers; it never fails open.
- **pre-existing finding** — a review finding tagged `[pre-existing]` right after its severity tag (`PRE_EXISTING_RE`): the defect is already on the base branch. It never blocks; step 4.5 files it once.
- **pre-existing key** — `<file>:<category>` or `<file>:<first 40 bytes of the description>`, written into the follow-up as `(pre-existing-key: <key>)` so the next ship that meets the same defect does not file it again.
- **live checkout** — the checkout behind `~/.claude/skills/ship-workflow` (a symlink made by `./sync.sh restore`). Every session on the machine runs it, uncommitted edits included, so it stays on `main`; ship-next Phase 1 warns otherwise (R-004).
- **command copy** — a `<repo>/.claude/commands/ship-*.md` file the old `/ship-init` copied in. They went stale; `remove_command_copies <repo>` clears them, and no repo needs one (R-004).
- **displaced** — what `./sync.sh restore` does to a real file or directory that sits where a link or a restored config belongs: moved to `~/.claude/.ai_system-displaced/<name>-<UTC time>`, never deleted.
- **land (mr mode)** — `/ship-land R-NNN` after the review merges: runs `/ship-compound` in a throwaway worktree at `origin/<base>` and pushes one `[skip ci]` push; review branches never write shared files (R-008).
- **Roadmap 檢視** — the Obsidian plugin in `obsidian-roadmap-view/` (R-013): a live, read-only, phone-first view of one project's ROADMAP for a person. `./sync.sh restore` copies it into `<vault>/.obsidian/plugins/roadmap-view/`; it is enabled by hand once.
- **ship-status file** — `<vault project>/ship-status/<R-NNN>.json`, written by `sn_status` at each ship-next phase (`brainstorm` … `done`, or `blocked` with a note). Observability only: a failed write is one WARN, never a failed ship.
- **現況 panel** — a mockup's `.panel.now` element (else its first non-`facts` `.panel`): the "as it is today" picture Roadmap 檢視 shows as the item's thumbnail.
- **spec review** — ship-next Phase 6 step 1.4 (R-016): every attempt, a read-only sub-agent compares `git diff <base>...HEAD` with the spec and writes `/tmp/ship-next-spec-<ID>-<attempt>.md`. `[spec:missing]`/`[spec:wrong]` block and quote the spec on an indented `Spec:` line; `[spec:extra]` is `[ponytail:yagni]`. `sn_spec_review_check` rejects a malformed report before counting.
- **grilling round** — how Phase 3 asks (R-016, after Matt Pocock's `grilling`): every question whose prerequisites are settled, numbered, each with a recommended answer worded so "yes" accepts it; facts are looked up by a sub-agent. Auto mode takes the recommended answer.
- **enforced rule** — a learned rule line in `docs/tdd-rules.d/` that carries ` · enforced by <check>` (R-017). A check catches the mistake, so the Phase 5 executor is not handed it; rules without the marker are **judgment rules**, the only ones rendered and capped. `tdd_rules_table` lists both.
- **lesson proof** — `tdd_rules_prove <red-ref> <cmd> <paths>` (R-017): the check, overlaid on a throwaway worktree at the mistake's commit, must fail there and pass on the fix. Compound step 6b records a lesson as enforced only with this proof.
- **door** — a ship's merge danger (R-021, after Matt Pocock's `pr` skill): `two-way` if a revert walks it back, `one-way` otherwise. The spec's Decisions state it (`Door: …`); `sn_door` escalates it to one-way on mechanical signals (migrations, new dependencies, deploy/CI files, base-branch `one_way_paths`). Two-way keeps the repo's merge mode (mr repos auto-merge after CI); one-way always waits for a human review.
- **cross-review** — ship-next Phase 6 step 1.3 (R-019): when Claude wrote the code (executor 1/2), `codex review --base <base>` reviews it too; its `[Pn]` findings are converted (P0/P1 block, P2 important, P3 nit), tagged `[codex]`, `[both]` when code review cited the same lines, and appended to the code review report. Skipped when codex was the executor; an unavailable codex only warns.
- **picked option (採用方案)** — the option a ROADMAP row says was built: `mockup 定案 X` or `方案 X 定案` on the row, else `方案 X` on a `↳` line that mentions a mockup. Roadmap 檢視 shows its mockup panel — the `.panel.opt<X>` whose heading starts with 方案/版面 X, else class `opt<X>` (R-024).
